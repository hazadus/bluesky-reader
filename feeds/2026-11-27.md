💬 Python Tip #331 (of 365):

Replace map and filter with generator expressions. 🧵

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3n3d3itr7cm2j)

----
**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 Each of these functions can be summed up in one line of Python:

def map(function, iterable):
    return (function(x) for x in iterable)

def filter(function, iterable):
    return (x for x in iterable if function(x))

(There's A LITTLE BIT MORE to them, but they're ESSENTIALLY THE SAME.)

[Открыть пост](https://bsky.app/profile/trey.io/post/3n3d3iucgpk25)

----
**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 Both predate the comprehension syntax, and combining them leads to some WEIRD code nesting:

list(map(square, filter(is_odd, numbers)))

That's a little bit inside-out looking. I find the comprehension version a lot more readable:

[square(n) for n in numbers if is_odd(n)]

[Открыть пост](https://bsky.app/profile/trey.io/post/3n3d3iuem7z2w)

----
**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 Comprehensions also don't require functions: we can stick the code we want to run right inside the comprehension:

(n**2 for n in numbers)  # vs map(lambda n: n**2, numbers)

If comprehensions had been added to Python first, I suspect map and filter wouldn't exist.

[Открыть пост](https://bsky.app/profile/trey.io/post/3n3d3iugftr2w)

----
**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 Folks often think of map, filter, and reduce as a trio.

I usually recommend avoiding functools.reduce also.

There's often an existing reduction function (sum, set.union, "".join) you could use instead.

Even when there's not, a "for" loop is often more readable than an equivalent reduce call.
