💬 Python Tip #271 (of 365):

Return, don't print. 🧵

If your function only seems to "work" in the REPL, it may be printing when it should be RETURNING.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwmlinle2y2m)

----
**🕒 00:35 👤 @trey.io (Trey Hunner)**
💬 The print function "outputs" to the TERMINAL.

The return statement "outputs" to the code that called your function.

The Python REPL blurs this distinction by printing every non-None return value:

>>> nth_fibonacci(20)
6765

Was that printed, or returned? It's unclear.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwmlinooth2i)

----
**🕒 00:35 👤 @trey.io (Trey Hunner)**
💬 We could find out by assigning a variable to the function's result:

>>> x = nth_fibonacci(20)
6765
>>> print(x)
None

Output appeared DURING THE CALL, and x got None (the default return value), so this function prints instead of returning.

**🕒 00:35 👤 @trey.io (Trey Hunner)**
💬 Functions that print are typically the surface-level ones, like a main function that calls other functions and displays results for a user. Other functions typically hand values BACK to the code that called them with "return".

Most functions should return instead of printing.

💬 Python Tip #273 (of 365):

Avoid needless wrapper functions. 🧵

This lambda does nothing but call len:

sorted(words, key=lambda s: len(s))

So pass len itself:

sorted(words, key=len)

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwoxqudlxn2v)

----
**🕒 23:20 👤 @trey.io (Trey Hunner)**
💬 It doesn't matter whether your function was made with a "def" block or a "lambda" expression: if it's a wrapper that could be deleted, consider deleting it.

def lowercase(s):
    return s.lower()

Use str.lower directly, or better yet, ask whether the function you ACTUALLY want already exists.

**🕒 23:20 👤 @trey.io (Trey Hunner)**
💬 Calling lower on a string is the same thing as passing that string to str.lower:

>>> name = "Python"
>>> name.lower()
'python'
>>> str.lower(name)
'python'

Methods are just functions attached to classes (see tip #39... misnumbered in the embed below).

That's the reason passing str.lower works.

**🕒 23:20 👤 @trey.io (Trey Hunner)**
💬 Functions are objects in Python.

Anywhere a function is expected (a key argument, a callback, map, defaultdict...), you can pass an EXISTING function instead of wrapping it:

key=str.lower      # not key=lambda s: s.lower()
defaultdict(list)  # not defaultdict(lambda: [])

💬 Python Tip #272 (of 365):

Do something or return something, but not both. 🧵

The list sort method returns None:

>>> numbers = [4, 2, 7, 1, 5]
>>> x = numbers.sort()
>>> print(x)
None
>>> numbers
[1, 2, 4, 5, 7]

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwoym5dxjm2b)

----
**🕒 23:35 👤 @trey.io (Trey Hunner)**
💬 The sort method modifies the list IN PLACE: mutating the list is its purpose.

Returning nothing indicates that an action happened.

append, extend, update, and most other mutating methods/functions follow this convention.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwoym5fzxm2e)

----
**🕒 23:35 👤 @trey.io (Trey Hunner)**
💬 Your own functions should follow this convention too.

If a function returns data AND mutates an object, callers may incorrectly assume that no object was mutated.

print(f"Median score: {median(scores)}")

It would be VERY surprising if median changed our scores list.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwoym5hk422v)

----
**🕒 23:35 👤 @trey.io (Trey Hunner)**
💬 There ARE exceptions: list.pop and dict.setdefault both mutate AND return.

But neither returns the object it mutated. When mutation is a function's primary purpose, returning a value isn't QUITE as confusing.

If your function does BOTH, consider whether that could be a gotcha.
