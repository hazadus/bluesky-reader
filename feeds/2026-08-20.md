**🕒 23:47 👤 @trey.io (Trey Hunner)**
💬 Python Tip #232 (of 365):

Try to avoid static methods in Python. 🧵

A static method is just a function that HAPPENS to live on a class. It doesn't know what instance it was called on, or even what class.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mtkglznnyk26)

**🕒 23:47 👤 @trey.io (Trey Hunner)**
💬 Static methods are usually helper functions that got attached to a class for organizational reasons:

class Hasher:
    ...

    @staticmethod
    def _checksum_matches(hash_object, checksum):
        checksum_bytes = bytes.fromhex(checksum)
        return checksum_bytes == hash_object.digest()

**🕒 23:47 👤 @trey.io (Trey Hunner)**
💬 Since that method is really just a function attached to a class, it could be moved to the module level instead:

def _checksum_matches(hash_object, checksum):
    checksum_bytes = bytes.fromhex(checksum)
    return checksum_bytes == hash_object.digest()

**🕒 23:47 👤 @trey.io (Trey Hunner)**
💬 Functions are great!

In Python, there's no reason to turn a function into a method if it doesn't need to be a method.

Modules already group related things together in Python. Your class doesn't need to do that job too.

If encapsulation is all you're after, modules do the job as well as classes.

----
**🕒 23:47 👤 @trey.io (Trey Hunner)**
💬 Sometimes a static method exists to be overridden.

Instead, consider accepting a callable:

class Hasher:
    def __init__(self, path, digest_hash=hashlib.sha256):
        self.path = pathlib.Path(path)
        self.digest_hash = digest_hash

Now customization doesn't even require inheritance.
