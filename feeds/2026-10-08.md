**🕒 17:27 👤 @trey.io (Trey Hunner)**
💬 Python Tip #281 (of 365):

Bundle your package into one runnable file with zipapp. 🧵

$ python3 -m zipapp src -m "greet.cli:main" -p "/usr/bin/env python3" -o greet.pyz
$ python3 greet.pyz
Hello from greet!
$ ./greet.pyz
Hello from greet!

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxeyaj46kv2x)

**🕒 17:27 👤 @trey.io (Trey Hunner)**
💬 That ".pyz" file is a zip file holding everything in src (here, yesterday's greet package) plus a __main__‍.py file that zipapp writes at its root:

# -*- coding: utf-8 -*-
import greet.cli
greet.cli.main()

Python runs that file, just like "python3 -m greet" runs "greet/__main__‍.py".

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxeyaj6hby2x)

----
**🕒 17:27 👤 @trey.io (Trey Hunner)**
💬 Running "python3 greet.pyz" works for any ".pyz" file.

The "-p" option adds a shebang line and makes the file executable (on Linux and macOS), so "./greet.pyz" works too.

On Windows, run "py greet.pyz" instead.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxeyaja4i32s)

----
**🕒 17:27 👤 @trey.io (Trey Hunner)**
💬 The ".pyz" extension is just a convention. If you rename it to greet and put it in a directory on your PATH, you'll have a greet command instead.

It's not a standalone binary, though: the system it's on still needs Python installed.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxeyajbncl2s)

----
**🕒 17:27 👤 @trey.io (Trey Hunner)**
💬 Note that third-party dependencies AREN'T bundled automatically. You'll need to install them into src first, with "pip install --target src".

And packages with C extensions (like NumPy) can't be imported from a zip file at all.
