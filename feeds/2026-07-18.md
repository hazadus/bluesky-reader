💬 Python Tip #198 (of 365):

Lock the dependencies for your Python scripts 🧵

After you start using inline script metadata to have uv automatically manage your script's dependencies (tip 197), how can you ensure the dependencies of your dependencies don't break your code?

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqvdg4uu3k2o)

----
**🕒 03:34 👤 @trey.io (Trey Hunner)**
💬 You could pin your dependencies, but you'd also want to pin the dependencies of your dependencies and such.

You could generate a lock file instead, which is actually possible with a uv script:

$ uv lock --script my_script.py

As long as you keep the lock file in the same directory, uv will use it.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqvdg4yn6k2o)

----
**🕒 03:34 👤 @trey.io (Trey Hunner)**
💬 But I don't want a bunch of .lock files cluttering up my ~/bin directory.

Also I don't want to copy/rename both the files whenever I copy/rename just one of them.

Fortunately there's a simpler way to effectively lock the dependencies in a uv script: exclude-newer.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqvdg4yo5s2o)

----
**🕒 03:34 👤 @trey.io (Trey Hunner)**
💬 Setting an "exclude-newer" timestamp to the current time ensures that anytime uv freshly installs dependencies for your script, it'll use the exact version of each package that you have installed right now (assuming you have the latest versions installed now).

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqvdg4yr3k2o)

----
**🕒 03:34 👤 @trey.io (Trey Hunner)**
💬 Before adding an exclude-newer line you might want to double check that you have the latest versions installed:

$ uv sync --script my_script.py --upgrade

And just as with yesterday's tip, you might want to consider using my uvrs command for this. It auto-timestamps with exclude-newer by default.

💬 Python Tip #199 (of 365):

Use uvx to try out tools without installing them 🧵

For example, "uvx fguess" installs & runs my fguess package in an isolated temporary environment.

This also doesn't JUST work with scripts. You can use uvx to try out Python packages in a REPL!

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqxfrmt24s2u)

----
**🕒 23:21 👤 @trey.io (Trey Hunner)**
💬 You can also use "uvx --with better-dedent python" to launch a Python REPL with the "better-dedent" package installed.

It even knows that you'll need Python 3.14+ to work with "better-dedent" so it'll launch the appropriate Python version (installing it first if you don't yet have Python 3.14).

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqxfrmtxgc2u)

----
**🕒 23:21 👤 @trey.io (Trey Hunner)**
💬 I use uvx all the time to try out a library before adding it to your project.

You can think of uvx as a wrapper around both "uv run" and "uv tool".

These two are basically equivalent:

$ uv run --with rich python
$ uvx --with rich python

And so are these:

$ uv tool run fguess
$ uvx fguess
