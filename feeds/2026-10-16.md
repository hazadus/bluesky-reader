**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 Python Tip #289 (of 365):

Add context to exceptions with add_note. 🧵

def load_config(path):
    try:
        return json.loads(Path(path).read_text())
    except json.JSONDecodeError as error:
        error.add_note(f"While parsing {path}")
        raise

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxz5x2thvg2u)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 The note shows up right below the error message:

Traceback (most recent call last):
  ...
json.decoder.JSONDecodeError: Expecting ',' delimiter: line 3 column 3 (char 22)
While parsing settings.json

The error message says which LINE has the problem, but not which FILE. Our note adds that context.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxz5x2wth32g)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 Why not raise a new exception with a better message?

A ValueError wouldn't match an "except json.JSONDecodeError" further up, and keeping the type is awkward:

raise json.JSONDecodeError(
    f"{error.msg} in {path}", error.doc, error.pos
) from error

Either way, you'd see two tracebacks.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxz5x2yov22d)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 A note is great for adding context the code that raised the exception couldn't know: which file, which row, which URL, which retry attempt...

Python 3.14's json module adds notes itself:

TypeError: Object of type set is not JSON serializable
when serializing dict item 'tags'

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 If you WANT to change the exception type, raise a new exception with "from" (see tip #143).

But to add context while keeping the original exception, use add_note and a bare "raise".

This is a Python 3.11+ feature, but 3.10 EOL'd last week, so it's safe to use everywhere now.
