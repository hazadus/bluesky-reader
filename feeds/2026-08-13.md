💬 Python Tip #224 (of 365):

Constants that are specific to a class often belong ON that class. 🧵

class Circle:
    max_radius = 100
    def __init__(self, radius):
        if radius > self.max_radius:
            raise ValueError("Too large")
        self.radius = radius

**🕒 03:08 👤 @trey.io (Trey Hunner)**
💬 Why make max_radius a class attribute instead of a module-level MAX_RADIUS constant?

Locality of behavior: the constant lives right next to the code that relies on it, and its name (Circle.max_radius) says exactly what it relates to.

**🕒 03:08 👤 @trey.io (Trey Hunner)**
💬 Class attributes can also be customized in subclasses, no method overriding needed:

class BigCircle(Circle):
    max_radius = 1_000_000

Since our initializer looked up self.max_radius (instead of hard-coding Circle.max_radius), every BigCircle instance picks up the larger limit automatically.

**🕒 03:08 👤 @trey.io (Trey Hunner)**
💬 One caution: class attributes are shared by every instance of a class.

For a constant, that sharing is the point. But a MUTABLE class attribute can be a gotcha (related to tips 222 & 223).

Class attributes are usually for constants (& dataclass fields). Per-instance state should go in __init__.
