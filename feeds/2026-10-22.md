**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 Python Tip #295 (of 365):

Avoid needless deep copying. 🧵

Often a deepcopy call can be replaced by a comprehension, a slice, or some other operation that makes new objects.

When you copy a list of dictionaries, you get a NEW list pointing to the SAME dictionaries.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3myhwpyn7l32a)

----
**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 So if you plan to mutate those dictionaries, a shallow copy isn't enough.

You could make a deep copy instead:

from copy import deepcopy

processed_data = deepcopy(tweet_data)
for tweet in processed_data:
    tweet["date"] = datetime.strptime(tweet["date"], "%b %d %Y")

[Открыть пост](https://bsky.app/profile/trey.io/post/3myhwpyq4ge26)

----
**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 Or we could avoid that deepcopy call by making a new list of new dictionaries instead:

processed_data = [
    {**tweet, "date": datetime.strptime(tweet["date"], "%b %d %Y")}
    for tweet in tweet_data
]

In Python, we usually prefer making NEW objects over mutating existing ones.

[Открыть пост](https://bsky.app/profile/trey.io/post/3myhwpyrsxx25)

----
**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 We tend to prefer shallow copies in Python: list(items), dict(mapping), slicing, and comprehensions all make new containers without copying the CONTENTS of those containers (tip #223's list(...) call is one example).

[Открыть пост](https://bsky.app/profile/trey.io/post/3myhwpz6q2p25)

----
**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 Within the standard library, deepcopy is used in about 8 files. list(...) is used in over 100.

If you don't mutate objects that don't belong to you, you'll rarely need deepcopy.

I'm not saying "never use deepcopy" (it certainly CAN be useful), just that every deepcopy call should be questioned.
