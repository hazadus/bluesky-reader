💬 Python Tip #227 (of 365):

Don't rely on clever implementation details. 🧵

In CPython, two 3's are identical:

>>> x = 3
>>> y = 3
>>> x is y
True

But two 300's are not always identical:

>>> x = 300
>>> y = 300
>>> x is y
False

Don't rely on this. Compare numbers with ==.

💬 In CPython, integers from -5 to 256 are created when Python launches, so every 200 is identical to every other 200.

Bigger numbers are only identical in situations where Python notices it has the same number:

>>> x, y = 300, 300
>>> x is y
True

💬 Short strings often get the same treatment:

>>> name = "Trey"
>>> name2 = "Trey"
>>> name is name2
True
>>> name3 = (name + "!")[:-1]
>>> name3 is name
False
>>> name == name3
True

These optimizations could change in any Python release, and other Python implementations do this differently.

💬 The lesson: when checking whether two objects represent the same data, use ==, not "is".

>>> x == y
True

The "is" operator is pretty much only used for sentinel values like None, where identity is the point.
