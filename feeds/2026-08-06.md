**🕒 23:38 👤 @trey.io (Trey Hunner)**
💬 Python Tip #218 (of 365):

Don't needlessly convert between data types. 🧵

Looping over a file once? There's no reason to convert it to a list first:

for line in my_file:
    print(line, end="")

"for" loops don't need a list. They accept ANY iterable.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3msh7lq5c2t2e)

----
**🕒 23:38 👤 @trey.io (Trey Hunner)**
💬 The same goes for LOTS of other data types.

If you're just looping over a set, there's no reason to convert it to a list first:

>>> colors = {'red', 'blue', 'yellow'}
>>> for color in colors:
...     print(color)
...
red
yellow
blue

Lists can be looped over, but so can any other iterable object.

[Открыть пост](https://bsky.app/profile/trey.io/post/3msh7lqckum2x)

----
**🕒 23:38 👤 @trey.io (Trey Hunner)**
💬 Needless type conversions make Python do extra work: building a whole new data structure that you're about to throw away.

With files, converting to a list also means reading the ENTIRE file into memory at once, even if you only needed one line at a time.

[Открыть пост](https://bsky.app/profile/trey.io/post/3msh7lqfdda2f)

----
**🕒 23:38 👤 @trey.io (Trey Hunner)**
💬 Before you reach for "list(...)", ask what the code you're passing that object to ACTUALLY needs.

If it just needs to loop, any iterable will do.

And yes, this is me talking about duck typing AGAIN from another angle: care about the BEHAVIOR a function needs, not the type you'll pass it.
