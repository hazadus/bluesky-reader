**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Python Tip #203 (of 365):

When you need precise decimal numbers, use decimal.Decimal 🧵

Floating point numbers have precision gotchas.

0.1 + 0.02 isn't 0.12:

>>> one_two = 0.1 + 0.02
>>> one_two == 0.12
False
>>> one_two
0.12000000000000001

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mravvosjsi2a)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 floats precisely represent binary numbers, not decimal ones.

For precise decimals, you can use decimal.Decimal:

>>> from decimal import Decimal
>>> one_two = Decimal("0.1") + Decimal("0.02")
>>> one_two == Decimal("0.12")
True
>>> one_two
Decimal('0.12')

Note that we pass strings to Decimal.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mravvow2x427)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Computers are optimized for binary arithmetic (not decimal), so Python's Decimal objects are slower than floating point numbers... but for many applications that performance trade off is a small one.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mravvp4uyd23)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 If speed is an issue, you can probably get away with using floating point numbers and then rounding to the desired precision whenever you need to display the numbers.

Here we're rounding to 4 digits after the decimal point:

>>> one_two
0.12000000000000001
>>> print(round(one_two, 4))
0.12

[Открыть пост](https://bsky.app/profile/trey.io/post/3mravvpa5za2e)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Every computation with a float adds some impreciseness to a calculation.

That might sound scary, but if your numbers are within a few orders of magnitude then even millions of additions and multiplications won't introduce a rounding error 4 decimal places out.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mravvpdrv52q)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 So, use decimal.Decimal when you need precision UNLESS you're doing a lot of computations and performance is a big concern.

Then do the math to determine the size of the error your calculations introduce and decide whether "just use floats and round before display" is good enough for your use case.
