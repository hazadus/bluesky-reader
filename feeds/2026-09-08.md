**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Python Tip #251 (of 365):

Avoid wildcard imports. 🧵

Using star imports, like "from something import *", makes for fragile code.

The Zen of Python ends with "Namespaces are one honking great idea -- let's do more of those!"

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3muzmbodjkf27)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Each module automatically makes a namespace, which is great: same-named variables in different modules never accidentally collide.

A wildcard import BREAKS that namespacing: "import *" dumps every name from one module into another.

[Открыть пост](https://bsky.app/profile/trey.io/post/3muzmbr2rv622)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 That can cause real bugs: "import *" from two modules and an upgrade in one of them may silently shadow a name from the other.

You might even end up relying on things you shouldn't, like the uuid module containing a pointer to the os module:

>>> from uuid import *
>>> os

[Открыть пост](https://bsky.app/profile/trey.io/post/3muzmbrjwb622)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Explicit imports make it easy to see where a name came from.

Every name is defined in the current module or listed in an import statement, so a text search answers "where did this come from?" No code analysis tool needed.

Explicit is better than implicit (also from the Zen of Python).
