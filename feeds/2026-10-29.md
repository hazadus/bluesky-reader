**🕒 20:54 👤 @trey.io (Trey Hunner)**
💬 Python Tip #302 (of 365):

Use // instead of truncating with int. 🧵

Do this:
mid_point = len(sequence) // 2

Not this:
mid_point = int(len(sequence) / 2)

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mz25ljsp2e2t)

----
**🕒 20:54 👤 @trey.io (Trey Hunner)**
💬 Between two integers, // divides and returns an integer directly.

It's also a bit more efficient than dividing to get a floating point number and then converting that back to an integer.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mz25lkm4pe2v)

----
**🕒 20:54 👤 @trey.io (Trey Hunner)**
💬 Two caveats before you replace every "int(a / b)":

1. // always rounds DOWN (like math.floor), while int truncates TOWARD ZERO:

>>> int(-5 / 2)
-2
>>> -5 // 2
-3

2. If either operand is a float, // returns a float:

>>> 52.0 // 4
13.0

I'd use // for dividing positive integers.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mz25ll3num2s)

----
**🕒 20:54 👤 @trey.io (Trey Hunner)**
💬 If you also need the remainder, consider using divmod instead:

>>> divmod(13, 5)
(2, 3)

That's equivalent to "(13 // 5, 13 % 5)".
