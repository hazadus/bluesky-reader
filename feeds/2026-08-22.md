💬 Python Tip #233 (of 365):

Don't return self from a method just to allow method chaining. 🧵

In Python, methods that mutate usually return None:

>>> numbers = [3, 1, 2]
>>> numbers.append(4)

Functions and methods either RETURN a thing or DO a thing, but usually not both.

#Python #DailyPythonTip

**🕒 04:47 👤 @trey.io (Trey Hunner)**
💬 It may be tempting to make a mutating method return self so that calls can be chained:

tasks = (
    TodoList()

    .add_task("Record screencast")

But that breaks the convention every other Python object follows: If a method mutates, it shouldn't return.

💬 The method chains you've seen in the wild work differently.

String methods, pathlib.Path methods, pandas DataFrame methods, and Django QuerySet methods all return NEW objects:

>>> name = "Trey Hunner"
>>> name.casefold().replace(" ", "_")
'trey_hunner'
>>> name
'Trey Hunner'

Nothing was mutated.

**🕒 04:47 👤 @trey.io (Trey Hunner)**
💬 If you want method chaining in your own class, design specifically for it:

class TodoList:
    def __init__(self, tasks=()):
        self.tasks = list(tasks)

    def with_task(self, task):
        return TodoList([*self.tasks, task])

Every chainable method should return a new object.

💬 Python Tip #234 (of 365):

Don't inherit from list or dict. You could end up with some weird bugs. 🧵

For example, don't do this:

class TwoWayDict(dict):
    def __setitem__(self, key, value):
        super().__setitem__(key, value)
        super().__setitem__(value, key)

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mtp4tfgtp22r)

----
**🕒 20:35 👤 @trey.io (Trey Hunner)**
💬 We customized the dict __setitem__ method to make a bi-directional dictionary.

>>> d = TwoWayDict()
>>> d[3] = 8
>>> d
{3: 8, 8: 3}

And it seems to work... except when it doesn't:

>>> d.update({9: 7})
>>> d
{3: 8, 8: 3, 9: 7}

That mapped 9 to 7, but not 7 to 9! 😦

----
**🕒 20:35 👤 @trey.io (Trey Hunner)**
💬 Python's various dict methods won't call our overridden dunder methods:

• The update(), __init__(), and setdefault() methods don't call __setitem__()
• The pop() method skips __delitem__()
• get() even skips __getitem__()!

Fixing every one of those methods by hand is tedious and easy to get wrong.
