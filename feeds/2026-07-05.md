💬 Python Tip #186 (of 365):

Use the errors argument when reading files with encoding issues. 🧵

Reading a file with the wrong encoding either raises a UnicodeDecodeError or silently produces mojibake (garbled text).

The "errors" argument provides control over the first case.

#Python #DailyPythonTip

**🕒 23:31 👤 @trey.io (Trey Hunner)**
💬 Which failure you get depends on the file. Invalid bytes in the chosen encoding raise an exception:

>>> p = pathlib.Path("p")
>>> p.write_text("café", encoding="cp1252")
>>> p.‍read_text(encoding="utf-8")
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe9 in position 3: unexpected end of data

**🕒 23:31 👤 @trey.io (Trey Hunner)**
💬 The "errors" argument can be used to avoid an exception in the case of invalid bytes

To substitute each bad byte for a replacement character:

>>> p.‍read_text(encoding="utf-8", errors="replace")
'caf�'

To silently drops bad bytes:

>>> p.‍read_text(encoding="utf-8", errors="ignore")
'caf'

**🕒 23:31 👤 @trey.io (Trey Hunner)**
💬 Trying to figure out what's actually in a file?

Set "errors" to "backslashreplace":

>>> p.‍read_text(encoding="utf-8", errors="backslashreplace")
'caf\\xe9'

Bad bytes appear as "\xNN" escape sequences where the actual raw numeric byte value is represented by the hexadecimal numbers after \x.

💬 The "errors" argument only helps when decoding fails. Mojibake happens when a decode appears to succeed but with the wrong encoding, so "valid" garbage characters are shown instead of any exception.

The "errors" argument is most useful when your file has some invalid noise in a mostly correct file.
