**🕒 03:16 👤 @trey.io (Trey Hunner)**
💬 PEP 8 recommends this for "non-public methods and instance variables".

The underscore doesn't STOP access:

>>> wh._digits

>>> wh._digits = "5551234567"

But when another Pythonista sees an underscore-prefix name, they'll think "that's odd... we're relying on an internal attribute".

**🕒 03:16 👤 @trey.io (Trey Hunner)**
💬 What about TWO leading underscores?

Avoid that. Writing self.__digits triggers "name mangling"... Python renames __digits to _PhoneNumber__digits.
It still doesn't stop access... it just puts the class name in the attribute name.

**🕒 23:48 👤 @trey.io (Trey Hunner)**
💬 Python Tip #231 (of 365):

Use class methods as alternate constructors. 🧵

>>> s = Square.from_area(100)
>>> s.length
10.0

The classmethod decorator makes a method that's meant to be called on the class itself (not on an instance of the class).

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mthw6wxoks2r)

----
**🕒 23:48 👤 @trey.io (Trey Hunner)**
💬 Instead of self (the instance), the first argument is cls (the class):

import math

class Square:
    def __init__(self, length, color=None):
        self.length = length
        self.color = color
    @classmethod
    def from_area(cls, area, color=None):
        return cls(math.sqrt(area), color)

[Открыть пост](https://bsky.app/profile/trey.io/post/3mthw6x4sms2r)

----
**🕒 23:48 👤 @trey.io (Trey Hunner)**
💬 Notice that from_area calls cls, not Square.

That means class methods play nicely with inheritance: calling from_area on a subclass of Square would return an instance of THAT SUBCLASS, which is exactly what users of the subclass would expect.
