💬 Python Tip #306 (of 365):

Don't use tuples for list-like data. 🧵

Do this:
colors = ["pink", "purple", "green", "blue"]

Not this:
colors = ("pink", "purple", "green", "blue")

💬 Tuples are TECHNICALLY just immutable lists, but their immutability isn't the primary reason that we use them.

💬 List-like data tends to be all of the same type and there's often lots of it.

Tuple-like data is often of different types, and there's a fixed quantity of it.

This is a list of tuples:

    ("Perth", 2_067_333),
    ("Lisbon", 2_971_587),

💬 Python Tip #309 (of 365):

Make dataclasses instead of named tuples. 🧵

Do this:
@dataclass
class Room:
    name: str
    number: int

Not this:
class Room(NamedTuple):
    name: str
    number: int

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mzg5nyvlkf2s)

----
**🕒 15:27 👤 @trey.io (Trey Hunner)**
💬 The biggest problem with named tuples is that... they're tuples.

They support ALL tuple behaviors, even concatenation:

>>> purple = Room("Purple", 301)
>>> blue = Room("Blue", 401)
>>> purple + blue
('Purple', 301, 'Blue', 401)

**🕒 15:27 👤 @trey.io (Trey Hunner)**
💬 The things I usually want from a named tuple are easy to get with a dataclass (some easier than others).

Attributes and equality checks work automatically.

For immutability, pass "frozen=True". For orderability, pass "order=True".

**🕒 15:27 👤 @trey.io (Trey Hunner)**
💬 If you need tuple unpacking, you could add a __iter__ method to your dataclass.

When you do want objects that ACT just like tuples, I'd reach for typing.NamedTuple instead of collections.namedtuple, since the syntax is nicer.

But I pretty much never have a need for named tuples anymore.

>>> import math
>>> math.pi

>>> print(f"{math.pi:.42f}")
