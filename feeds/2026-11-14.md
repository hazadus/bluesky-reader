💬 Python Tip #318 (of 365):

Don't shadow built-in names like list, sum, and input. 🧵

Name a variable list and you can't call the list function from the same scope:

>>> list = [1, 2, 3]
>>> list(range(3))
TypeError: 'list' object is not callable

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3n2bvco6h2o2u)

----
**🕒 16:12 👤 @trey.io (Trey Hunner)**
💬 We haven't overwritten the list function, it's just inaccessible for now:

>>> del list
>>> list(range(3))
[0, 1, 2]

Built-in names aren't reserved words, Python just has a separate scope for built-ins. A global or local variable with the same name as a built-in will shadow it (see tip #225).

[Открыть пост](https://bsky.app/profile/trey.io/post/3n2bvcokple2y)

**🕒 16:12 👤 @trey.io (Trey Hunner)**
💬 The names you use for function arguments also count. This WORKS, but I'd recommend against it:
def has_no_duplicates(list):
    return len(set(list)) == len(list)

Name your arguments something helpful instead:
def has_no_duplicates(numbers):
    return len(set(numbers)) == len(numbers)

**🕒 16:12 👤 @trey.io (Trey Hunner)**
💬 A name that shadows a built-in only hides it INSIDE that function, so sometimes I shadow on purpose.

I'd rather see someone call 'prompt("A number", type=int)' than 'prompt("A number", type_=int)'.

In this case, I'd accommodate the function caller over the function's maintainer.

----
**🕒 16:12 👤 @trey.io (Trey Hunner)**
💬 The built-ins I see shadowed most often are list, id, input, sum, max, min, next, type, and object.

Shadowing built-ins can often be avoided by using a more specific name (numbers instead of list).

When there isn't one, you could use a trailing underscore (id_, type_) or an abbreviation (obj).
