**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 Python Tip #229 (of 365):

Don't overuse classes. 🧵

Writing Python code does NOT require writing classes.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mtcrubmbuk2i)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 Unlike many programming languages, you can accomplish quite a bit in Python without ever making a class.

The most common reason to write a class is that a framework REQUIRES one (e.g. Django Model classes).

The second most common reason: you have data & functionality that clearly belong together.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mtcrubrhv22i)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 A good sign you might want a class: you keep passing the same object (or group of objects) into many different functions.

server = get_conn(host, user, passwd)
uids = get_uids(server)
message = get_message(server, uid)
close_conn(server)

Note that server object being passed around.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mtcrubriuc2i)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 If you're NOT passing shared state around, start with a function.

A class with __init__ plus one other method is usually just a function disguised as a class.

Python's built-in data types are pretty great. You may find that you don't often need to make your own classes... and that's fine!
