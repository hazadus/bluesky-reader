💬 Python Tip #217 (of 365):

Think in terms of the minimum viable duck 🧵

In other words: "what's the least this object needs to do to work in this context?"

Sometimes the answer is a solid noun: iterable.

Sometimes it's a fuzzier duck: an object with a write() method.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mse4gejmpj2f)

**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 For example, csv.reader is usually given a file object... but it accepts ANY iterable of delimited lines:

>>> import csv
>>> rows = ['a,b,c', '1,2,3']
>>> list(csv.reader(rows))
[['a', 'b', 'c'], ['1', '2', '3']]

**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Likewise, print()'s file argument can be ANY object with a write method:

class FakeFile:
    def __init__(self): self.text = ""
    def write(self, text): self.text += text

It never checks the type of "file":

>>> f = FakeFile()
>>> print("Hi!" file=f
>>> f.text
'Hi!
'

It just calls .write()!

💬 Knowing the minimum viable duck can simplify your code.

Downloaded a string of CSV data from the web?

You don't need to write it to a file just to parse it. You can pass data.splitlines() straight to csv.reader.

**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Duck typing isn't just about noticing what an object can do: it's also about considering the minimum viable duck for YOUR functions

Assuming a list will be passed? Consider assuming a sequence.

Assuming a sequence? Consider assuming an iterable.

Your code will be more general-purpose as a result.
