**🕒 14:48 👤 @trey.io (Trey Hunner)**
💬 Say your command-line tool has a "--plot" option that uses matplotlib.

If "import matplotlib.pyplot" sits at the top of your module, every run of your tool takes about 0.4 seconds to import matplotlib... even runs that never plot anything!

That's ~25 times longer than Python takes to start!

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxjqamn45v2g)

----
**🕒 14:48 👤 @trey.io (Trey Hunner)**
💬 One fix is to move the import into the function that needs it:

def plot_results(results):
    import matplotlib.pyplot as plt
    ...

Now matplotlib is only imported when plot_results is called.

Tip #256 used this trick to work around a circular import. Here it's to reduce startup time instead.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxjqamvvfv2g)

----
**🕒 14:48 👤 @trey.io (Trey Hunner)**
💬 Python 3.15 also adds EXPLICIT lazy imports, with the lazy keyword:

lazy import matplotlib.pyplot as plt

The import can stay at the top of the file, but the module isn't loaded until the first time plt is used.

Until you upgrade to Python 3.15, a function-level import is pretty reasonable.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxjqamxi6v2g)

----
**🕒 14:48 👤 @trey.io (Trey Hunner)**
💬 For either import style, I'd only do this for imports that are slow AND optional.

And you probably don't want lazy imports in a web app. They'd make startup faster but the first request using each module slower. Slower startup and faster requests is usually the better tradeoff.
