💬 Python Tip #280 (of 365):

Make your package runnable with a __main__‍.py file. 🧵

greet
├── cli‍.py
├── __init__‍.py
└── __main__‍.py

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxczmeonyn25)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 When you run a package with "python3 -m", Python runs its __main__‍.py file:

$ python3 -m greet
Hello from greet!

Without that file, the package can't be run directly:

$ python3 -m food_utils
No module named food_utils.__main__; 'food_utils' is a package and cannot be directly executed

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxczmeqzga26)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 A __main__‍.py file is usually tiny. It imports the real entry point and calls it:

from .cli import main

main()

Putting the actual code in a submodule (like cli‍.py) means it can also be IMPORTED without running anything (see tip #253 on import side effects).

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxczmf5amv2n)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 Python's own packages do this too: "python3 -m zipfile" works because zipfile has a __main__‍.py file.

And as of Python 3.14, "python3 -m json" pretty-prints JSON like "python3 -m json.tool". I opened the PR for that small change.

More in my article on Python's many command-line utilities 👇
