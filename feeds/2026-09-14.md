**🕒 02:24 👤 @trey.io (Trey Hunner)**
💬 Importing a module runs its code, including its imports.

So importing users.models runs users.tasks, which imports from users.models... which isn't finished yet:

ImportError: cannot import name 'User' from partially initialized module 'users.models' (most likely due to a circular import)

[Открыть пост](https://bsky.app/profile/trey.io/post/3mvh2lfcoc22r)

----
**🕒 02:24 👤 @trey.io (Trey Hunner)**
💬 To fix a circular import, ask why these two modules depend on each other.

If they're so tightly coupled they should be one module, merge them.

If one module is doing too much, move code into a third module that both can import.

The circle breaks once one module stops importing the other.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mvh2lfezso2k)

----
**🕒 02:24 👤 @trey.io (Trey Hunner)**
💬 Not ready to refactor or can't? Move the import inside the function that needs it:

def send_welcome(user):
    from .tasks import send_welcome_email
    send_welcome_email(user)

That's often called a LAZY IMPORT: the module isn't loaded until the function runs.

**🕒 02:24 👤 @trey.io (Trey Hunner)**
💬 Python 3.15 (out October 1) adds a real "lazy import" statement, so the import can stay at the top of the file:

Both fix the ERROR without breaking the dependency, so it's more of a workaround than a fix. Breaking the dependency is ideal when possible.

**🕒 19:27 👤 @trey.io (Trey Hunner)**
💬 You could use a "from" import like this:

from datetime import datetime

Now datetime means the class.

But if you also want the date class, you're importing that name too, and hoping no local date variable shadows it. I definitely use the variable name date, so this is a problem for me.

import datetime

**🕒 19:27 👤 @trey.io (Trey Hunner)**
💬 You could instead import the whole datetime module but rename it to dt:

import datetime as dt

dt‍.datetime.now()
dt‍.date.today()
dt.timedelta(days=3)

There's no variable shadowing concern, since date and time are still namespaced. And dt‍.datetime.now() is pretty readable.
