**🕒 05:15 👤 @trey.io (Trey Hunner)**
💬 Python Tip #222 (of 365):

Be careful with mutable default values in function definitions. 🧵

This class is buggy:

class TodoList:
    def __init__(self, tasks=[]):
        self.tasks = tasks
    def add_task(self, task):
        self.tasks.append(task)

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3msrubexz4s27)

----
**🕒 05:15 👤 @trey.io (Trey Hunner)**
💬 Default argument values are evaluated ONE time: when a function is defined.

So every TodoList object made without args shares the SAME list:

>>> mon = TodoList()
>>> tue = TodoList()
>>> mon.add_task("Run")
>>> tue.tasks
['Run']

We added a task to Monday's list & it showed up in Tuesday's list! 😦

[Открыть пост](https://bsky.app/profile/trey.io/post/3msrubeyxfk27)

----
**🕒 05:15 👤 @trey.io (Trey Hunner)**
💬 One common fix: use None as the default and make a new list inside the function.

Another fix: use a tuple as the default and make a new list from it:

class TodoList:
    def __init__(self, tasks=()):
        self.tasks = list(tasks)

Now the shared default doesn't matter!

----
**🕒 05:15 👤 @trey.io (Trey Hunner)**
💬 Note that the list(...) call is doing the important work in that example: it makes a NEW list out of whatever iterable it's given.

Mutable default values aren't ALWAYS trouble... the trouble comes from MUTATING a shared object. More on that in tomorrow's tip!
