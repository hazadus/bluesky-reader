💬 Python Tip #191 (of 365):

Compare iterables item-by-item with all() & zip(). 🧵

The == operator won't compare a list and a tuple by their contents:

>>> [1, 2, 3] == (1, 2, 3)
False

And two generators can't be compared by their contents at all.

**🕒 03:27 👤 @trey.io (Trey Hunner)**
💬 You can compare iterables item-by-item, regardless of their type like this:

>>> a = [1, 2, 3]
>>> b = (1, 2, 3)
>>> all(x == y for x, y in zip(a, b, strict=True))
True

This works for lazy iterables (like generators) and iterables of unhashable items.

**🕒 03:27 👤 @trey.io (Trey Hunner)**
💬 Why "strict=True"?

Without it, zip() stops at the shorter iterable, so "[1, 2]" and "[1, 2, 3]" would look equal.

With "strict=True", zip raises a ValueError when the iterables have different lengths, so a length mismatch won't silently pass as "equal".

💬 Python Tip #192 (of 365):

To compare two iterables while counting duplicates but ignoring order, use Counter. 🧵

A Counter object tallies how many times each item appears. Two counters are equal when every item appears the same number of times, regardless of order.

#Python #DailyPythonTip

💬 The second check here is False because one iterable has an extra 2:

>>> from collections import Counter
>>> Counter([1, 2, 2, 3]) == Counter([3, 2, 1, 2])
True
>>> Counter([1, 2, 3]) == Counter([1, 2, 2, 3])
False

More on ignoring order when comparing iterables: https://pym.dev/iterable-equality/#ignoring-order-when-comparing-iterables
