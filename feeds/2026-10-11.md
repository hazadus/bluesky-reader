**🕒 14:48 👤 @trey.io (Trey Hunner)**
💬 Python Tip #284 (of 365):

Import from another directory by adding it to sys.path. 🧵

sys.path.insert(0, str(Path(__file__).parent / "vendored_utils"))

This is a bit of a hack. It works great in your own project, but I wouldn't want to see it in an installable package.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxmapjxwz72g)

----
**🕒 14:48 👤 @trey.io (Trey Hunner)**
💬 The sys.path list contains the directories Python searches when looking for modules and packages to import.

It's a plain list of strings, so you can add to it at runtime. Once your module's directory is in there, you can import your module as usual:

import silly_module

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxmapk22gd2d)

----
**🕒 14:48 👤 @trey.io (Trey Hunner)**
💬 Unlike sys.path.append(...), sys.path.insert(0, ...) goes to the front. Python checks these directories in order, so YOUR module is found first, even if another directory has a module with the same name.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxmapk3td22d)

----
**🕒 14:48 👤 @trey.io (Trey Hunner)**
💬 Why not use this in an installable package?

sys.path is shared by the whole program. A library that inserts its own directories could shadow modules in the code that imports it.

I'd rather see a package explicitly list dependencies than vendor those dependencies in a way that could break MY code.
