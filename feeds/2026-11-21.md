**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 Python Tip #325 (of 365):

Avoid returning defaultdict objects. 🧵

A defaultdict is handy while building a dictionary:

by_color = defaultdict(list)
for item in items:
    by_color[item.color].append(item‍.name)

But once you're done, it'll keep auto-creating missing keys.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3n2tyolhp5o2e)

----
**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 Every missing key lookup silently adds the new key with a default value:

>>> by_color["mauve"]
[]
>>> "mauve" in by_color
True

These READ operations will change the data structure without raising an exception, quietly pretending the key was there all along.

[Открыть пост](https://bsky.app/profile/trey.io/post/3n2tyom3dsv27)

----
**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 That's a problem for any code that expects missing keys to raise a KeyError.

I sometimes use setdefault instead of defaultdict:

by_color = {}
for item in items:
    colors = by_color.setdefault(item.color, [])
    colors.append(item‍.name)

[Открыть пост](https://bsky.app/profile/trey.io/post/3n2tyom5ob32x)

----
**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 That setdefault call sets the key to an empty list ONLY if it's not already there. And since it returns the value, we can append right away.

This gives me key defaulting when I need it while using a plain dictionary, so regular key lookups will still raise a KeyError.

[Открыть пост](https://bsky.app/profile/trey.io/post/3n2tyom7vlw2m)

----
**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 Converting with dict(by_color) before returning works too, but if you're converting anyway, I'd consider using the setdefault method instead.

I most often use defaultdict when I want EVERY key lookup to have a default, meaning a KeyError should NEVER happen. In my experience, that's pretty rare.
