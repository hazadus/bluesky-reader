💬 Python Tip #195 (of 365):

Globally install Python-powered command-line tools with "uv tool install" 🧵

Whenever I want to install a command-line tool that happens to be Python powered, but I want it to be globally available everywhere on my machine, I use "uv tool".

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqmscq4pvf2e)

----
**🕒 18:06 👤 @trey.io (Trey Hunner)**
💬 To install my Python-powered countdown-cli, I do this:

$ uv tool install countdown-cli
Resolved 2 packages in 169ms
Installed 2 packages in 5ms
 + click==8.3.2
 + countdown-cli==2.2.1
Installed 1 executable: countdown

Then I can run "countdown" ANYWHERE on my machine to start a countdown timer.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqmscqb3gy2x)

----
**🕒 18:06 👤 @trey.io (Trey Hunner)**
💬 When a new version of my countdown-cli tool comes out, I install it with:

$ uv tool upgrade countdown-cli

"uv tool upgrade --all" will upgrade all of my CLI tools. I usually prefer to upgrade one at a time though.

To see all the uv-managed commands:

$ uv tool list

Run "uv help tool" for more.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mqmscqdmsp2q)

**🕒 18:06 👤 @trey.io (Trey Hunner)**
💬 Why not just globally install with pip?

Well, when it comes time to upgrade you'll need to remember which of the 4 versions of Python that you have installed was managing that particular command.

**🕒 18:06 👤 @trey.io (Trey Hunner)**
💬 Also, did you accidentally install the tool in multiple versions of Python?

And what happens when a different global tool wants a different version of a particular dependency?

I used to recommend pipx to solve these problems, but "uv tool" now checks all the same boxes as pipx AND it's faster.
