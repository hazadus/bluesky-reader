💬 Python Tip #282 (of 365):

Read your package's data files with importlib.resources. 🧵

>>> from importlib import resources
>>> resources.files("dinner").joinpath("recipes.json").read_text()
'{"tacos": ["tortillas", "beans", "salsa"]}\n'

**🕒 13:27 👤 @trey.io (Trey Hunner)**
💬 The usual alternative is to build a path relative to the current module:

from pathlib import Path

DATA_DIR = Path(__file__).parent
recipes = (DATA_DIR / "recipes.json").read_text()

That works as long as your package lives in a regular directory on disk.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxh3aukdhe2x)

**🕒 13:27 👤 @trey.io (Trey Hunner)**
💬 But if you bundle your package with zipapp (see tip #281), __file__ points INSIDE the ".pyz" file, so reading that path fails:

NotADirectoryError: [Errno 20] Not a directory: 'dinner.pyz/dinner/recipes.json'

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxh3auyfwg26)

----
**🕒 13:27 👤 @trey.io (Trey Hunner)**
💬 The files function returns an object that works like a pathlib.Path:

from importlib import resources

recipes = (resources.files("dinner") / "recipes.json").read_text()

Unlike __file__, files asks Python's import system where the data lives, so it always works.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxh3av2cs62u)

----
**🕒 13:27 👤 @trey.io (Trey Hunner)**
💬 For a quick and sloppy script, Path(__file__).parent is fine.

For a proper package (and especially one that others will install), I'd use importlib.resources.files instead.
