💬 Python Tip #226 (of 365):

Don't assign to global variables from within a function. 🧵

You CAN do this in Python. But you really shouldn't.

Yesterday's tip noted that assignments within a function NORMALLY make local variables.

But they don't always...

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mt3srreufk2c)

----
**🕒 04:15 👤 @trey.io (Trey Hunner)**
💬 Python's "global" statement is the exception:

>>> phrase = "Hi world"
>>> def set_phrase(name):
...     global phrase
...     phrase = f"Hello {name}"
...

"global" is an escape hatch that makes assignments write to the global scope:

>>> set_phrase("Trey")
>>> phrase
'Hello Trey'

[Открыть пост](https://bsky.app/profile/trey.io/post/3mt3srrg3hk2c)

----
**🕒 04:15 👤 @trey.io (Trey Hunner)**
💬 But I don't recommend using "global".

Instead of assigning to a global variable, RETURN the value:

>>> def make_phrase(name):
...     return f"Hello {name}"
...

And leave it up to the caller to assign, if they'd like to:

>>> phrase = make_phrase(Trey")
>>> phrase
'Hello Trey'

----
**🕒 04:15 👤 @trey.io (Trey Hunner)**
💬 Functions typically accept inputs through their arguments and provide outputs with their return values.

Changing global state from within a function makes it difficult to trace when and why state changed.
