💬 Python Tip #268 (of 365):

Show relative paths with relative_to. 🧵

Absolute paths are noisy:

>>> print(path)
/home/trey/taxes/archived/2017/invoices
>>> taxes
PosixPath('/home/trey/taxes')
>>> print(path.relative_to(taxes))
archived/2017/invoices

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwfh7gnpm72b)

----
**🕒 04:30 👤 @trey.io (Trey Hunner)**
💬 This is handy when searching a file tree:

>>> for path in taxes.rglob("*.csv"):
...     print(path.relative_to(taxes))
...
2026/expenses.csv
2026/dividends.csv

The code works with full paths internally, but users only see short paths.

**🕒 04:30 👤 @trey.io (Trey Hunner)**

Passing "walk_up=True" (Python 3.12+) allows ".." in the result instead, but I rarely need that.

💬 Python Tip #269 (of 365):

Walk directory trees with Path.walk. 🧵

The walk method (Python 3.12+) is the pathlib version of os.walk. For each directory in the tree, you get the directory's path, a list of its subdirectory names, and a list of its file names.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwhesjmfng2a)

----
**🕒 22:52 👤 @trey.io (Trey Hunner)**
💬 Example:

>>> for directory, sub_directories, files in taxes.walk():
...     print(directory, sub_directories, files)
...
taxes ['archived', '2026'] []
taxes/archived ['2017'] []
taxes/archived/2017 ['invoices'] []
taxes/archived/2017/invoices [] ['soylent.pdf']
taxes/2026 [] ['expenses.csv']

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwhesjphfk2v)

----
**🕒 22:52 👤 @trey.io (Trey Hunner)**
💬 The names are strings, not Path objects. Join them to the directory:

>>> for directory, sub_directories, files in taxes.walk():
...     for name in files:
...         if name.endswith(".csv"):
...             print(directory / name)
...
taxes/2026/expenses.csv

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwhesjs3hc2e)

----
**🕒 22:52 👤 @trey.io (Trey Hunner)**
💬 Why does walk return strings for the names instead of Path objects?

Speed.

When working with 100,000+ paths, the time it takes to create a new Path object is somewhat noticeable... unless you're also opening each file. Then Path creation time will probably be swallowed by the file open time.

**🕒 22:52 👤 @trey.io (Trey Hunner)**
💬 For just finding files by pattern, rglob is simpler. But walk is better when you care about the directory structure, like skipping whole directories by removing them from sub_directories before walk descends into them:

if ".git" in sub_directories:
    sub_directories.remove(".git")
