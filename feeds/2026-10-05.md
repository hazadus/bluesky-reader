💬 Python Tip #277 (of 365):

For substring checks, use the "in" operator. 🧵

Python has a special operator that's meant JUST for checking whether one thing is contained inside another:

>>> part = "Python"
>>> whole = "I enjoy writing Python code."
>>> part in whole
True

#Python #DailyPythonTip

**🕒 02:46 👤 @trey.io (Trey Hunner)**
💬 Folks new to Python often reach for the string find method:

found = whole.find(part) != -1

That "-1" feels a bit magical.

And checking for a substring with the index method requires exception handling:

try:
    whole.index(part)
    found = True
except ValueError:
    found = False

**🕒 02:46 👤 @trey.io (Trey Hunner)**

**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 Python Tip #278 (of 365):

Always include a __init__‍.py file in your Python packages. Even an empty one. 🧵

food_utils
├── fruits‍.py
├── __init__‍.py
└── non_fruits‍.py

A package is a directory that Python treats like a module.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mx5yojughw2m)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 When you import the package, the module you get back IS the __init__‍.py file:

>>> import food_utils
>>> food_utils

An empty __init__‍.py is pretty common and it's fine for your code to live in submodules.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mx5yojxtwz26)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 It IS POSSIBLE to make a Python package that doesn't have a __init__‍.py file.

This is called an IMPLICIT NAMESPACE PACKAGE, and these act a little differently from other packages.

Their __file__ attribute is None, and many tools that look for packages (pytest, for example) may not find them.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mx5yojzldt2x)

----
**🕒 22:47 👤 @trey.io (Trey Hunner)**
💬 Implicit namespace packages exist for a niche use case (splitting one package across multiple directories).

Unless that's what you're deliberately doing, add a __init__‍.py file. No accidental implicit namespace packages.
