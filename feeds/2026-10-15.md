**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 Python Tip #288 (of 365):

Show a value's repr with "!r" in f-strings. 🧵

>>> name = "Trey"
>>> print(f"Name: {name}")
Name: Trey
>>> print(f"Name: {name!r}")
Name: 'Trey'

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxwnj46npk2d)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 By default, f-strings use the human-readable representation of an object (str instead of repr). The "!r" suffix forces the repr version.

Most objects have the same str and repr, but some (like strings and datetime‍.date objects) don't.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxwnj4d6gn25)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 I mostly use "!r" in error messages, where it makes the output more helpful:

>>> n = "4"
>>> print(f"Expected an int, got {n}")
Expected an int, got 4
>>> print(f"Expected an int, got {n!r}")
Expected an int, got '4'

The repr makes it clearer that n is a string, but it's supposed to be a number.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxwnj4ejl62x)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 I also use "!r" in __repr__ methods, so the output looks like code:

>>> class Person:
...     def __init__(self, name):
...         self‍.name = name
...     def __repr__(self):
...         return f"{type(self).__name__}({self‍.name!r})"
...
>>> Person("Trey Hunner")
Person('Trey Hunner')
