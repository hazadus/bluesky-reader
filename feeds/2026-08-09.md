**🕒 00:34 👤 @trey.io (Trey Hunner)**
💬 ABC stands for "abstract base class".

Inheriting from an ABC gets you two things:

1. isinstance and issubclass checks will work nicely (i.e. isinstance(x, Sequence))

2. Python will complain LOUDLY if you forgot to implement a required method, instead of failing later in some subtle way

**🕒 00:34 👤 @trey.io (Trey Hunner)**
💬 Prefer not to inherit? You can REGISTER your class with an ABC instead:

from collections.‍abc import MutableSequence

class MyCustomList:
    ...

MutableSequence.register(MyCustomList)

Registered classes are treated as "virtual subclasses": isinstance checks will see your objects as sequences.

**🕒 00:34 👤 @trey.io (Trey Hunner)**
💬 You can think of registering as an OPT-IN DUCK: if it says it's a duck, it's a duck.

Third-party libraries tend to either inherit from a collections.‍abc class or register with one. That's why isinstance checks against those ABCs are so reliable.

This is the flip side of yesterday's tip (219).
