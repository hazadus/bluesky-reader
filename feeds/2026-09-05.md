💬 Python Tip #247 (of 365):

Test file processing code with tempfile. 🧵

These are the 2 most useful tempfile utilities:

• NamedTemporaryFile: makes a file that Python deletes automatically
• TemporaryDirectory: makes a directory that Python deletes automatically

💬 A test that makes real files in a temporary directory:

def test_make_rst_from_md_file():
    with TemporaryDirectory() as tmpdir:
        path = Path(tmpdir, "example‍.md")
        path.write_text("# Example")
        make_rst_from_md_file(path)
        assert path.with_suffix(".rst").is_file()

**🕒 00:08 👤 @trey.io (Trey Hunner)**
💬 Need just one file? NamedTemporaryFile deletes its file as soon as the "with" block ends... which may be a problem if we actually want to USE the file.

As of Python 3.12, you can pass "delete_on_close=False": closing the file doesn't delete it; exiting the "with" block does.

**🕒 00:08 👤 @trey.io (Trey Hunner)**
💬 Using pytest? Use its tmp_path fixture instead. It passes a fresh temporary directory (as a pathlib.Path object) to each test that uses it.

Unlike tempfile, pytest keeps the temporary files from your last 3 test runs by default, which can help when debugging a failing test.

**🕒 00:08 👤 @trey.io (Trey Hunner)**
💬 Writing tests with unittest, or making a temporary file for a subprocess to use? Use tempfile.

Whichever you use, don't make temporary files manually. There's no reason to make a randomly named file yourself, pass it around, and remember to delete it when you're done.

Use a helper for that!
