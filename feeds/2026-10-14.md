💬 Python Tip #287 (of 365):

Read tracebacks from the bottom up. 🧵

When Python encounters an exception that isn't handled in your code, it prints out a traceback.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxu4yg4qdk2x)

----
**🕒 18:02 👤 @trey.io (Trey Hunner)**
💬 For example:

Traceback (most recent call last):
  File "count‍.py", line 12, in 
    main()
  File "count‍.py", line 9, in main
    count_to(stop)
  File "count‍.py", line 4, in count_to
    for n in range(1, number+1):
TypeError: can only concatenate str (not "int") to str

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxu4ygbdf42d)

----
**🕒 18:02 👤 @trey.io (Trey Hunner)**
💬 The very last line describes WHAT happened: the exception type and a (hopefully) helpful message. That's the line you might search for online.

The lines above it describe WHERE you were in the code, with the deepest frame last.

Each frame shows the file, line number, function, and line of code.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxu4ygchd32s)

----
**🕒 18:02 👤 @trey.io (Trey Hunner)**
💬 That's why the first line says "most recent call last": the most recent call is shown LAST, at the bottom.

So the reading order is:

1. Last line: what went wrong
2. The lines just above: where it went wrong
3. Keep moving up to see what code called that code and what code called that code, etc.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxu4ygdljr2g)

----
**🕒 18:02 👤 @trey.io (Trey Hunner)**
💬 The deepest frame won't always be YOUR code. It could be code from some other module besides your own.

So sometimes you'll need to skip some of the bottom frames to find your own code.
