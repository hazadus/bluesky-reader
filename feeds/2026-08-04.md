💬 Python Tip #216 (of 365):

Embrace duck typing in Python. 🧵

In Python, we often care more about the behavior of an object than its type.

We say "if it looks like a duck and quacks like a duck, it's a duck".

We check for duckness, we don't test DNA, we observe behavior.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3msblxgibcn26)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Instead of asking "what TYPE can I use here?", ask "does my object have the BEHAVIOR that's expected here?"

Python's sum function doesn't care whether it gets a list:

>>> sum({1, 1, 2, 3, 5})
12
>>> sum(range(5))
10

It only cares whether it can LOOP OVER the object we give it.

[Открыть пост](https://bsky.app/profile/trey.io/post/3msblxglqer2f)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Because Pythonistas prefer to describe objects by their behavior, we tend to nounify verbs:

• iterable: anything you can loop over
• sequence: an indexable iterable that has a length
• mapping: a dictionary-like object
• callable: anything you can call

The behavior is what matters, not the type.

**🕒 18:12 👤 @trey.io (Trey Hunner)**
💬 Duck typing is why Python's docs and error messages talk about "iterable", "file-like object", and "path-like object" instead of naming specific classes.

>>> sum(2)
TypeError: 'int' object is not iterable

Python isn't complaining that we didn't pass a list. It's complaining missing BEHAVIOR.
