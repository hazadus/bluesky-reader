💬 Python Tip #263 (of 365):

Parse messy dates with the third-party dateutil library. 🧵

>>> from dateutil.parser import parse
>>> parse("September 20, 2026")
datetime.datetime(2026, 9, 20, 0, 0)
>>> parse("20 Sep 2026 14:30")
datetime.datetime(2026, 9, 20, 14, 30)

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mvxrupbqam24)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 With strptime, you need to know the format in advance. If your date strings tend to differ, dateutil can guess the format from each string.

It handles time zone offsets too:

>>> parse("Sun, 20 Sep 2026 14:30:00 -0700")
datetime.datetime(2026, 9, 20, 14, 30, tzinfo=tzoffset(None, -25200))

[Открыть пост](https://bsky.app/profile/trey.io/post/3mvxrupem632s)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Of course, guessing has limits. Is "01/02/2026" January 2nd or February 1st?

>>> parse("01/02/2026")
datetime.datetime(2026, 1, 2, 0, 0)
>>> parse("01/02/2026", dayfirst=True)
datetime.datetime(2026, 2, 1, 0, 0)

The default is month-first, so ambiguous input still needs a hint from you.
