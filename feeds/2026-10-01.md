**🕒 22:01 👤 @trey.io (Trey Hunner)**
💬 Python Tip #274 (of 365):

Prefer to name your functions. 🧵

Instead of this:
sorted(items, key=lambda item: int(item.split()[0]))

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwtubgqihh23)

----
**🕒 22:01 👤 @trey.io (Trey Hunner)**
💬 I'd usually write this:
def by_quantity(item):
    quantity, name = item.split()
    return int(quantity)

sorted(items, key=by_quantity)

The name by_quantity says what we're sorting by. And a "def" allows tuple unpacking instead of a hard-coded "[0]" index.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mwtubh5y4v2n)

----
**🕒 22:01 👤 @trey.io (Trey Hunner)**
💬 A lambda is a function without a name. Ask help what it is and it'll say VERY little: "".

That anonymity has costs:

• No name to explain the INTENT
• No docstring
• Limited to a single expression
• A syntax that Python users often parse more slowly

**🕒 22:01 👤 @trey.io (Trey Hunner)**
💬 I DO occasionally use "lambda". Defining a function on the same line you pass it somewhere is convenient.

Functions are objects (see tip #34), so pass them around freely... but use "lambda" conservatively.

If a function is important, it deserves a name.
