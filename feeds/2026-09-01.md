💬 Python Tip #243 (of 365):

Write automated tests. 🧵

You can test manually (run your code to make sure it works), or write automated tests: code that tests your code, like this:

def test_no_tax():
    assert calculate_total([3.50, 13.75], apply_tax=False) == 17.25

💬 Manual testing is fine for a throwaway script.

But for code that's serious and will likely stick around, I'd write automated tests.

Every time you change your code, your automated tests can tell you whether you broke something... without you needing to manually check every possible scenario.

**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Python Tip #244 (of 365):

Use a seed to test code that relies on randomness. 🧵

generate_code returns random characters, but this test passes properly every time:

def test_generate_code():
    random.seed(5)
    assert generate_code() == "YJ6P9462VAT7H2BF"

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3muhyzbko2h2u)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 The utilities in Python's random module generate PSEUDORANDOM numbers using a deterministic algorithm.

The random module's seed function sets the random number generator's initial state, so if we call the same random functions in the same order, we'll get the exact same numbers.

[Открыть пост](https://bsky.app/profile/trey.io/post/3muhyzdarja2o)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 This means our tests can rely on deterministic and predictable behavior.

This determinism is also why the random module isn't recommended for security-sensitive randomness.

If someone could see many consecutive pseudorandom outputs, they MIGHT be able to predict future outputs.

[Открыть пост](https://bsky.app/profile/trey.io/post/3muhyzdf47f2q)

**🕒 18:04 👤 @trey.io (Trey Hunner)**
