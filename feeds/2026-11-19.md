**🕒 03:01 👤 @trey.io (Trey Hunner)**
💬 Python Tip #322 (of 365):

Remove a key that might not exist with a default pop value. 🧵

Do this:
session.pop("username", None)

Not this:
if "username" in session:
    del session["username"]

The dictionary pop method deletes a key and returns its value.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3n2n3gqegwc26)

----
**🕒 03:01 👤 @trey.io (Trey Hunner)**
💬 Like "del", pop raises a KeyError for a missing key.

But pop accepts an optional second argument, which acts as a default value if the key isn't there:

>>> rooms = {"Pink": "Room 403", "Ocean": "Room 205"}
>>> rooms.pop("Garden", "Not Found")
'Not Found'

[Открыть пост](https://bsky.app/profile/trey.io/post/3n2n3gqgwpn2m)

----
**🕒 03:01 👤 @trey.io (Trey Hunner)**
💬 That default is also handy when you WANT the value, if there is one.

Do this:
source = session.pop("source", None)

Not this:
if "source" in session:
    source = session["source"]
    del session["source"]
else:
    source = None

The pop method does ALL of that work for us.

**🕒 03:01 👤 @trey.io (Trey Hunner)**
💬 You could use "del" and catch the KeyError instead (see tip #140):

try:
    del session["username"]
except KeyError:
    pass

The pop method sidesteps the EAFP vs. LBYL choice, but some may find this EAFP approach clearer when you don't need the value.

💬 Python Tip #323 (of 365):

You're allowed to rely on dictionary order. 🧵

>>> fruit_counts = {"apple": 2, "banana": 4, "mango": 1}
>>> for fruit in fruit_counts:
...     print(fruit)
...
apple
banana
mango

Dictionaries maintain the insertion order of their keys.

#Python #DailyPythonTip

**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 You may have heard that dictionaries are unordered or that we shouldn't rely on their order.

That USED to be true. Dictionaries WERE unordered until Python 3.6 and the order was an implementation detail until 3.7.

Dictionaries ARE ordered, but they're not sequences (you can't get the nth item).

**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 So collections.OrderedDict is only useful for move_to_end, popitem(last=False), and order-SENSITIVE equality checks.

Relying on dictionary order is a bit uncommon, though it can sometimes be handy to use the same data structure for both key lookups and iteration.
