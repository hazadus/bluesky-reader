**🕒 02:28 👤 @trey.io (Trey Hunner)**
💬 Python Tip #249 (of 365):

Monkey patch cautiously... and only in your automated tests. 🧵

Monkey patching means fundamentally changing how a module or class works WITHOUT editing its code, by reassigning one of its attributes at runtime.

In tests, it can simplify things.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3muvhjwe7dt24)

**🕒 02:28 👤 @trey.io (Trey Hunner)**
💬 Need to test a function that talks to a weather API? You could temporarily replace the function that makes the network request:

def test_forecast_summary():
    with patch("weather.fetch_forecast", return_value={"high": 75}):
        assert forecast_summary("Portland") == "High of 75"

[Открыть пост](https://bsky.app/profile/trey.io/post/3muvhjwhfmk24)

**🕒 02:28 👤 @trey.io (Trey Hunner)**
💬 pytest's monkeypatch fixture and unittest.mock.patch both undo the patch when the test ends.

Monkey patching can VERY QUICKLY complicate things.

It's common to accidentally patch the wrong fully qualified name by patching the module that DEFINES a function instead of the one that USES it.

[Открыть пост](https://bsky.app/profile/trey.io/post/3muvhjwjq7q2y)

----
**🕒 02:28 👤 @trey.io (Trey Hunner)**
💬 But more importantly, tests that patch many things are tests that might be testing at the wrong level: unit/small tests that patch lots of stuff are often much less helpful than integration/functional tests that ensure the code ACTUALLY does what it's supposed to.

[Открыть пост](https://bsky.app/profile/trey.io/post/3muvhjwmdnq2r)

----
**🕒 02:28 👤 @trey.io (Trey Hunner)**
💬 In tests, keep your monkey patching minimal, and avoid it when you can.

Outside of tests, I'd try to avoid it pretty much entirely. Code that works by swapping out someone else's functions at runtime is hard to reason about and can be VERY fragile.
