💬 Python Tip #225 (of 365):

Avoid creating local variables that share a name with a global variable. 🧵

This is called SHADOWING, and it can make for confusing code.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mszbiswqps2r)

----
**🕒 04:00 👤 @trey.io (Trey Hunner)**
💬 Assigning to a variable inside a function normally makes a LOCAL variable:

>>> phrase = "Hi!"
>>> def set_phrase(name):
...     phrase = f"Hello {name}"
>>> set_phrase("Trey")
>>> phrase
'Hi!'

The global phrase never changed. The function makes a LOCAL phrase that disappears when it returns.

----
**🕒 04:00 👤 @trey.io (Trey Hunner)**
💬 Shadowing can even break code that LOOKS like it should work:

>>> def set_phrase(name):
...     print(phrase)
...     phrase = f"Hello {name}"
...
>>> set_phrase("Trey")
UnboundLocalError: cannot access local variable 'phrase' where it is not associated with a value

----
**🕒 04:00 👤 @trey.io (Trey Hunner)**
💬 Within each function, every variable name is EITHER local or global. It can't be both. Python determines the local variables for a function right after it's defined (not when it's called).

In that last function, Python saw an assignment to phrase, which made it local (for the ENTIRE function).

**🕒 04:00 👤 @trey.io (Trey Hunner)**
💬 Using two variables with the same name in two different scopes is confusing.

If you find yourself shadowing a global variable, consider renaming one of your two variables.

More: https://pym.dev/local-and-global-variables/
