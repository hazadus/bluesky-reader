**🕒 03:15 👤 @trey.io (Trey Hunner)**
💬 If __init__ stores the given list directly:

class TodoList:
    def __init__(self, tasks): self.tasks = tasks
    def add_task(self, task): self.tasks.append(task)

Then mutating one object's list mutates the other's:

>>> mon.add_task("Practice")
>>> tue.tasks
['Meditate', 'Teeth', 'Practice']

**🕒 03:16 👤 @trey.io (Trey Hunner)**
💬 The fix: make a copy as the object is created.

You could use the list copy method, but I prefer list(...):

class TodoList:
    def __init__(self, tasks=()): self.tasks = list(tasks)

Why? list() accepts ANY iterable: a list, a tuple, a generator, etc.

Most iterables don't have a copy method.

💬 Notice that this also fixes yesterday's mutable default argument gotcha (tip 222).

The deeper issue wasn't really about default values: it's about multiple variables pointing to the SAME mutable object.

When your initializer accepts a mutable object that you plan to mutate, consider copying it.
