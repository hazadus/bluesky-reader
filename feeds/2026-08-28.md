class Version:
    ...  # self.‍parts is (major, minor, patch)

**🕒 03:32 👤 @trey.io (Trey Hunner)**
💬 NotImplemented signals to Python: "I don't know how to do this, go ask the other object."

That's how "3 == 3.0" works: the integer's __eq__ returns NotImplemented, so Python asks the float.

>>> (3).__eq__(3.0)
NotImplemented
>>> (3.0).__eq__(3)
True

**🕒 03:32 👤 @trey.io (Trey Hunner)**
💬 Why not return False instead?

Because returning False means Python NEVER asks the other object, even if that object knows how to compare itself to yours.

You could end up with "a == b" being True while "b == a" is False! 😬

**🕒 03:32 👤 @trey.io (Trey Hunner)**
💬 When both sides return NotImplemented, == falls back to an identity check, but other operators raise:

>>> Version(3, 14, 2) < "3.14.2"

This is one of the few places where strict type checking is used over duck typing.

**🕒 22:22 👤 @trey.io (Trey Hunner)**
💬 Python Tip #240 (of 365):

Dunder methods are meant to be DEFINED, not called. 🧵

Do this:
str(today)

Not this:
today.__str__()

Why avoid calling dunder methods?

Mostly because you're not supposed to...

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mu6fm3dzwu2v)

----
**🕒 22:22 👤 @trey.io (Trey Hunner)**
💬 But dunder methods and the operations they power also aren't one-to-one:

>>> n = 10
>>> m = 2.5
>>> n / m
4.0
>>> n.__truediv__(m)
NotImplemented

"n / m" does more than n.__truediv__(m): if that returns NotImplemented, Python calls m.__rtruediv__(n) to ask the OTHER object to try the division.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mu6fm3i2vw2f)

----
**🕒 22:22 👤 @trey.io (Trey Hunner)**
💬 Dunder methods are a contract between Python and whoever wrote the class: Python calls them, we use the operations they power.

Whenever I see a dunder method call, I think "something low-level is going on here".

Usually there's a friendlier equivalent: an operator, a built-in function, etc.

----
**🕒 22:22 👤 @trey.io (Trey Hunner)**
💬 That low-level call is sometimes necessary though!

When overriding a dunder method, you may need super().__getitem__(key), since super()[key] doesn't work.

More on avoiding dunder methods: https://pym.dev/avoid-dunder-methods/
