**🕒 05:59 👤 @trey.io (Trey Hunner)**
💬 Python Tip #320 (of 365):

Use "in" to check whether a dictionary has a key. 🧵

Do this:
if color not in quantities:
    print(f"Uh oh! There's no value for {color}")

Not this:
if not quantities.get(color):
    print(f"Uh oh! There's no value for {color}")

#Python #DailyPythonTip

**🕒 05:59 👤 @trey.io (Trey Hunner)**
💬 That get check is only equivalent to a "does the key exist" check as long as the values in our dictionary will never be falsey:

>>> quantities = {"pink": 3, "green": 0}
>>> not quantities.get("green")
True
>>> "green" in quantities
True

The "in" operator is for containment checks (see tip #45).

**🕒 05:59 👤 @trey.io (Trey Hunner)**
💬 So when SHOULD you use the get method?

When you need to look up a key while getting a default value if the key is missing:

count = quantities.get(color, 0)

The get method IS handy, but don't use it when you ACTUALLY need a containment check.

💬 Python Tip #321 (of 365):

Loop over dictionary keys explicitly with keys(). 🧵

>>> counts = {"computers": 2, "cats": 1, "ducks": 3}
>>> for name in counts.keys():
...     print(name)
...

**🕒 21:01 👤 @trey.io (Trey Hunner)**
💬 Looping over a dictionary gives keys (see tip #45), so that keys method call is unnecessary.

It isn't meaningfully slower: keys returns a view, not a copy.

But when I loop over dictionary keys, I always prefer to call the keys method to make my code a bit more explicit.
