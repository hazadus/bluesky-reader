**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Python Tip #235 (of 365):

Don't use super() when "self" would work instead🧵

super() has one primary job: calling the parent class's version of a method you're overriding.

A super() call that isn't doing that job probably shouldn't be there.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mtresvia3j2z)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Here's a subclass of a tree-like Node class:

class DoublyLinkedNode(Node):
    ...
    def parents(self):
        return super().parents()

That parents method may as well not exist. If we deleted it, Python would find Node.parents on its own. That's what inheritance DOES.

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 This super() call is also unnecessary:

class DoublyLinkedNode(Node):
    ...
    def depth(self):
        return sum(1 for _ in super().parents())

We never overrode parents, so self.parents() finds the same method as super().parents().

And if parents ever IS overridden, we'd skip the new version.

**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 So when is super() actually useful?

When you need to customize a method while inheriting its original behavior:

class DoublyLinkedNode(Node):
    def __init__(self, name, parent=None):
        super().__init__(name=name, parent=parent)
        self.children = []

**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Extending a method you're overriding? Call super().

Fully replacing it? Don't.

Just calling an inherited method? Use self instead of super().
