**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 Python Tip #292 (of 365):

Keep "try" blocks small with an "else" clause. 🧵

try:
    count = int(text)
except ValueError:
    print("That's not a number")
else:
    print(f"Counting to {count}")

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3myafbsoesp22)

----
**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 The "else" block runs only if the "try" block finished without raising an exception.

Why not put that print call at the bottom of the "try" block instead?

try:
    count = int(text)
    print(f"Counting to {count}")
except ValueError:
    print("That's not a number")

[Открыть пост](https://bsky.app/profile/trey.io/post/3myafbu3wny2o)

----
**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 Two reasons: correctness and clarity.

If that print call ever raised a ValueError (or whatever exception we're catching), we'd handle it as if the CONVERSION had failed.

Also, the smaller the "try" block is, the easier it is to see which line we expect an exception from.

[Открыть пост](https://bsky.app/profile/trey.io/post/3myafbu5nfx2s)

----
**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 So when possible, the only thing that should go in a "try" block is code we're trying to catch an exception on.

Sometimes the "else" isn't strictly necessary: the code after it can't raise the caught exception, or the "except" block exits the function.

[Открыть пост](https://bsky.app/profile/trey.io/post/3myafbu73pu2x)

----
**🕒 15:03 👤 @trey.io (Trey Hunner)**
💬 I often use "else" even then, because it more clearly indicates "this part is the SUCCESS path" to anyone who reads the code.

Bonus tip: I also sometimes leave an unnecessary "else" on an "if" statement for readability's sake. More on that 👇
