**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 Python Tip #185 (of 365):

Normalize Unicode strings before comparing them. 🧵

Some Unicode characters can be written in more than one way.

Python's == won't consider them equal even if they look identical.

Use unicodedata.normalize() to fix this.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mptniun4s62k)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 The letter "é" can be stored two ways:

• As a single precomposed character (U+00E9)
• As e plus a combining accent (U+0065 + U+0301)

Both look the same, but Python treats them as different strings:

>>> x = "café"
>>> y = "café"
>>> x == y
False
>>> len(x), len(y)
(4, 5)

[Открыть пост](https://bsky.app/profile/trey.io/post/3mptniuquqm2g)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 unicodedata.normalize converts both forms to the same representation:

>>> from unicodedata import normalize
>>> normalize("NFC", x) == normalize("NFC", y)
True

"NFC" (Normalization Form Composed) is a common choice for text comparison. It combines decomposed characters into their precomposed form.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mptniutm7p2h)

----
**🕒 18:04 👤 @trey.io (Trey Hunner)**
💬 For case-insensitive comparisons, combine unicodedata.normalize with the string casefold method.

>>> def norm(s): return normalize("NFC", s).casefold()
>>> norm("CAFÉ") == norm("café")
True

The string casefold method is for case-insensitive comparisons, but it doesn't normalize at all.
