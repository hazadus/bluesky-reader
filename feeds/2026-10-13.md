💬 Python Tip #286 (of 365):

Know your way around the Python docs. 🧵

The docs at dochttps://docs.python.org/3/ve many different types of pages.

It's helpful to note which kind of page you're on and consider whether you're in the right place.

#Python #DailyPythonTip

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxrmkcahfa2d)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 The most common page types, roughly in order of importance:

• Library reference: built-ins and standard library modules
• How-to pages
• The tutorial: for programmers new to Python
• Language reference: for folks implementing a Python interpreter
• C API reference: for hooking into Python from C

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxrmkcdzlp2w)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 Those first two are where I most often WANT to be.

Unfortunately, while searching, I often end up in the C API reference or the language reference instead... 🙃

There are other notable pages too: the glossary, "what's new" pages, the deprecations page, and the FAQ pages, among others.

[Открыть пост](https://bsky.app/profile/trey.io/post/3mxrmkcgc2b2u)

----
**🕒 18:03 👤 @trey.io (Trey Hunner)**
💬 Two more docs habits I'd recommend adopting:

1. Don't use the docs site's search box: a web search with "site:docs.python.org" usually works much better (try "string methods").
2. Use the "Copy" button on code blocks: it copies just the code, without the >>> prompts or output.

**🕒 18:03 👤 @trey.io (Trey Hunner)**
